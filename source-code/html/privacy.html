A responsible planner

Ethics & privacy reflection

A study tool should help people organise their work without asking them to give up unnecessary information.

Collect only what is useful

StudyCourt asks for a task title, course code and name, due date, description and optional notes. It does not ask for a legal name, address, student number or contact details. This keeps the data focused on planning.

Input checks reject blank required fields, invalid dates and overlong text. Clear messages tell the user what needs correction without silently changing the task. The delete button asks for confirmation so an accidental click does not remove work immediately.

How the data is stored

Tasks are saved in this browser’s local storage and are not sent to a server by this project. Signing out clears the session flag but does not erase the local task list. A user should avoid entering sensitive information in task notes, especially on a shared computer.

The login in this course exercise is written in front-end JavaScript. Someone who can inspect the code or browser storage can bypass it. It is therefore only a basic access check, not secure authentication. A real service would need a server, protected password handling, secure sessions and a clear deletion and backup policy.

Design choices and limits

The interface labels required fields, explains errors next to the input, provides keyboard-friendly controls and uses a confirmation dialog for deletion. Tasks are displayed as text rather than inserted as HTML, which helps prevent user-entered markup from running in the page.

Browser-local storage avoids account creation and cloud sharing, but it also means data is tied to one browser and can disappear if browser data is cleared. The project has no cross-device backup. These limits are stated in the planner so users can make an informed choice.
